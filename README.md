# Translation Bench（翻译工作台）

一个面向本地 OpenAI 兼容模型服务的批量文档翻译工具。界面采用三栏布局：左侧配置、中间任务队列、右侧原文与译文对照。

## 功能

- 批量导入 Markdown、纯文本、字幕、DOCX、EPUB、带文字层 PDF 和扫描 PDF
- 模型 token 级流式显示当前译文，并按原文物理行实时对齐
- 总任务进度与当前文件进度
- 失败任务自动重试、手动重试和优先处理
- 在对照视图中单行重译，或从任务列表重译整个文件
- 选中文件后可从右侧单独翻译、重译、中断当前文件并跟随其实时进度
- 中断或失败时保留已经完成的行检查点，再次开始会从下一条未完成内容继续
- 双击译文行直接编辑，按 Enter 或点击对号保存并同步覆盖输出文件
- 单项任务删除并二次确认，可选择同时删除磁盘译文及其缓存记录
- 右侧一键清除当前文件译文、续译断点及磁盘输出，同时保留原文任务
- 一键清除完成记录和恢复缓存，同时保留磁盘译文
- 原文与译文逐行对照，可拖动调整栏宽
- 每个原文位置独立生成，流式译文由程序直接绑定到对应物理行
- 三档上下文模式：尽量全文、邻近上下文、独立单元
- 最近已确认译文保持术语、称谓和语气一致
- 后端终端按请求编号显示每次实际发送的完整 JSON、模型回复、结束原因和重试错误
- 本地模型请求一请求一连接，避免复用 llama-server 已关闭的 SSE 连接造成固定重试等待
- 长单元按目标语言预留更充足的输出空间；若模型仍以 `finish_reason=length` 截断，会在上下文允许范围内自动提高 `max_tokens` 并立即重试，不再用相同上限空等
- 剧情、技术、字幕、商务、学术等翻译风格
- 保留 Markdown 标题、列表、引用、行内标记和代码块
- 支持 Markdown、纯文本、SRT、WebVTT、DOCX、EPUB 与 PDF
- DOCX/EPUB 翻译后写回原容器，保留样式结构、图片、链接和其他非正文资源
- PDF 默认严格在原文本区域中替换译文，放不下时自动寻找可容纳的最大字号，不改变页面布局；目录页会清理损坏的点线字形并重建标题、点线和页码
- PDF 可按文件任意多选翻译页面，未选的封面、插图等页面原样保留
- 大型二进制文档从浏览器流式上传并直接写入磁盘，不再转换为 Base64；扫描 PDF 按所选页面逐页 OCR、逐页释放图像内存并复用识别缓存
- 刷新页面后恢复本地任务列表，并识别已经生成的匹配结果

## 环境要求

- Python 3.10 或更高版本
- 一个提供 `/v1/chat/completions` 接口的 OpenAI 兼容模型服务，例如 llama.cpp `llama-server`
- 默认配置面向 `Hy-MT2-7B-Q6_K`，模型别名为 `hy-mt2-7b`
- 现代桌面浏览器

DOCX、EPUB、字幕和文本流程仅使用 Python 标准库；PDF 提取、OCR 与输出需要安装项目依赖。导入、缓存、请求体、PDF 内容流和提取文本均不设置固定的 MB 上限。二进制文件会从浏览器直接流式写入内部缓存，避免 Base64 和 JSON 造成数倍瞬时内存占用；扫描页也会逐页渲染、识别和释放。实际可处理规模仍受可用内存、磁盘空间、页数与页面像素尺寸影响；异常压缩比、过量页数、加密和格式完整性等非体积检查仍然生效。

## 快速开始

1. 安装依赖：

   ```powershell
   py -3 -m pip install -r requirements.txt
   ```

2. 单独启动你的模型服务，并确认其 OpenAI 兼容接口可以访问。
3. 启动翻译工作台：

   ```powershell
   py -3 app.py 9000
   ```

4. 浏览器访问 <http://127.0.0.1:9000>。
5. 在左侧填写模型服务地址、模型名和必要的 API 密钥，然后点击“测试连接”。
6. 拖入 `.md`、`.txt`、`.srt`、`.vtt`、`.docx`、`.epub` 或 `.pdf` 文件并开始翻译。

Windows 用户也可以复制 `start.example.bat` 为本地 `start.bat` 后使用。`start.bat` 已被 Git 忽略，适合加入你自己的模型启动路径或本机设置。

## 默认配置

| 配置 | 默认值 | 说明 |
|---|---:|---|
| 服务地址 | `http://127.0.0.1:8081` | OpenAI 兼容模型服务 |
| API 密钥 | `local-qwen` | 本地服务的占位鉴权字符串；可按实际服务修改或留空 |
| 模型名 | `hy-mt2-7b` | 应与服务端公开的模型名一致 |
| 上下文长度 | `65536` | 不应超过服务端实际上下文长度 |
| 思考模式 | 关闭 | 翻译默认直接生成译文；Qwen3.5 等模型可按请求切换 |
| PDF 严格原位替换 | 开启 | 超出原文字框时缩小字号；不重排页面、不新增续页 |
| 上下文模式 | 尽量全文 | 可切换为邻近上下文或独立单元 |
| 近期译文单元 | `12` | 携带最近的完整原文与确认译文；长文模式也作为窗口前向重叠，设为 `0` 可关闭 |
| 长文后向重叠 | `6` | 全文超出预算时，固定语义窗口额外包含的后续完整单元数 |
| 翻译风格 | 自动判断 | 也可以选择固定风格 |

## 翻译与上下文流程

程序先按原文物理行和 Markdown 结构确定不可变化的输出位置。每次模型请求只翻译当前一个位置，流式 token 直接写入这行，不依赖模型生成行号、JSON 键或保持多行数量，因此某行生成异常不会把后面的译文挤到错误位置。

三档模式只改变模型收到的参考范围，不改变输出和写回方式：

- `尽量全文`：能放下时附带全文原文，放不下时按标题、段落空行和完整单元使用有重叠的固定语义窗口。
- `邻近上下文`：只附带配置数量内的最近确认译文和后续原文，不重复发送全文。
- `独立单元`：只发送当前待译单元，不携带文章前后文；预填开销最低，但跨段术语、称谓和指代的一致性最弱。

三种模式下，每次请求都只要求模型输出当前一个程序已定位的单元。极长的单个物理行只在完整句末拆分，翻译后重新合并回原位置。

SRT 和 WebVTT 使用独立的格式解析器：序号、cue id、时间轴、`WEBVTT` 头部以及 `NOTE`、`STYLE`、`REGION` 控制区块不会发给模型，只有字幕正文参与翻译。UTF-8 BOM 和 CRLF/CR 会在内部统一处理，保存文本译文时再恢复原文的 BOM 与换行风格。

DOCX 会从正文、表格、页眉页脚、脚注和尾注中提取可见段落；EPUB 会按 OPF spine 阅读顺序提取 XHTML 标题、段落、列表和表格单元，并保留 `<br>` 等显式换行边界。翻译后程序把每个稳定单元写回原 ZIP 容器，图片、链接、样式表和未参与翻译的资源保持不变。导入时会预先校验全部 ZIP 成员的大小、CRC 和压缩算法，避免翻译结束后才发现图片等附件损坏。混合行内格式会按原文字段长度把译文重新分配到既有文本节点，因此能保留大部分强调和链接范围，但不同语言长度差异很大时，强调边界可能与原文略有偏移。

PDF 采用逐页原位替换策略。普通页面按文字层的稳定句段提取；复杂多栏或 Form 页面由 `pdfplumber` 直接生成带坐标的版面文本块，预览、翻译和回填共用同一组块，不再用另一套文本结果事后猜测位置。没有文字层的页面则由 RapidOCR 在受控分辨率下识别文字框：每页单独渲染，识别完成就释放像素内存，识别框和阅读顺序写入对应原文缓存旁的内部 OCR 缓存，后续预览、翻译、重译和输出不会重复识别同一页。OCR 同样按通用的版面区域和栏位从上到下排序，并过滤低置信度结果、孤立艺术字母、纯页码和暂不可靠的竖排文字；没有识别到正文的插图页原样跳过。输出扫描页时保留整张原页图片，仅用各原文字行边缘采样出的背景色局部遮盖原字，再在 OCR 文本框内写入译文。

多栏页面会先按贯穿页面的水平留白划分上下内容区域，再在每个区域内按左栏到右栏、栏内从上到下排序，避免把下方说明插入上方跨栏文章的上下文。提取器还会在内部记录区域、栏位和栏内位置：同一区域由上一栏末尾流向下一栏顶部且字体相近时，明确提示模型把译文直接衔接；只有缺标点、小写开头等文字线索时仅交给模型结合上下文判断；标题、列表和跨区域边界则明确视为新单元。该内部信息不会写入预览或输出文件。带 CropBox 的双页封面只读取实际可见区域；仅用字形轮廓裁剪图像的艺术页会自动视为不可安全替换的美术内容，整页原样保留，不再把单个字母送入模型。可可靠恢复的异常字距和碎片化普通标题会先重组为完整单词或文本框。目录页使用单独的逐行映射：只把标题和页码作为干净单元送入翻译，忽略无法映射为 Unicode 的装饰点线，输出时再把可信页码放回右侧并绘制点线，避免乱码方框。文本框样式按主要文字颜色判断，标题在系统存在覆盖目标文字的粗体时会嵌入粗体。PDF 提取结构带版本号；解析规则升级后，浏览器会从本地原文缓存自动刷新预览并清除不能安全对齐的旧译文，磁盘中的旧输出不会自动删除。生成时程序只移除已经映射并准备替换的页面直接文字，再把译文写入对应文本区域；无法映射的 Form/Pattern 页眉、标志字和其他页面装饰会保留，因此页面尺寸、纸张背景、插图、边框、表格线、链接和大部分矢量设计仍可保留。默认开启“严格原位替换”：译文超出原框时通过二分搜索缩小到可容纳的最大字号，最低 1pt，不会重排页面或新增续页；若页面无法安全定位或缩小后仍放不下，会报告具体页码并停止生成。关闭该开关才会启用旧版逐页重排兼容行为。

选中 PDF 后，右侧标题栏可打开页码面板，逐页多选并使用全选、反选或清空；例如可只翻译 `3、4、6、9–12` 页，直接跳过中间插图。任务只提取和翻译所选页面；输出 PDF 会逐页复制未选页面而不修改。扫描 PDF 首次导入只 OCR 第 1 页并自动打开页码面板，避免尚未选页就识别整本书；确认页面后才识别新增选择且复用已经缓存的页面。页面选择会进入浏览器恢复状态、运行任务和输出元数据，修改选择时会清除旧译文与续译断点，防止不同页面集合的结果混用。旧版连续起止页状态仍可自动读取。严格模式不会产生续页，因此原 PDF 的页面数量和顺序保持不变。

这不是完整的专业排版或图像修复引擎：原位模式会尽量保留文本框位置、相对字号和原文填充颜色，但会使用覆盖目标语言的字体，不能完美还原字重、字距、艺术字和复杂文字特效。扫描页中的原文已经烙在图片像素里，局部底色遮盖无法重建原文字后方的复杂纹理；跨图案标题、弧形字、竖排字、手写字、低清扫描、复杂表格和异常多栏仍应人工检查。加密 PDF 会在导入时明确拒绝，请先解除密码保护。生成中日韩译文 PDF 时系统还需安装覆盖译文字符的对应字体，推荐 Noto Sans CJK；程序会嵌入已验证的字体，缺字时停止生成而不是输出方框。阿拉伯文、希伯来文等 RTL 输出还依赖 ReportLab 的额外 BiDi 组件，当前缺少组件时同样会停止生成。

二进制原文缓存在项目内部的 `.translation-sources/`，浏览器只保存缓存标识、所选 PDF 页面集合和提取后的预览文本，避免把整份 Base64 文档写入 localStorage。删除任务或清空任务列表时会同步释放对应原文缓存。EPUB 的 spine 正文若已加密则不支持；只加密字体或图片等非正文资源可以保留。PDF 的稳定预览文本和页面选择集中保存在 `.translation-state.json`，因为 PDF 内部的视觉换行不能稳定反推程序的原始翻译单元边界；清除缓存会删除这份恢复信息，但不会删除磁盘译文。

这套流程请求数更多，但当前 7B 翻译模型只需专注一个明确单元，准确度和位置稳定性高于一次生成整篇结构化结果。

整个文件重译不会把旧版译文喂回模型；在尽量全文和邻近上下文模式下，本轮已经完成的新译文会作为后续一致性参考。单行重译会把该行旧译文作为待校订稿，并按照当前上下文模式附带参考。

## 输出与页面恢复

翻译结果保存在本地 `outputs/` 目录，并可从网页单独下载或打包下载。输出文件会添加目标语言后缀，例如 `.zh.md`、`.en.txt`。

任务列表和可用的原文内容会保存在当前浏览器的 IndexedDB 中，localStorage 仅作小状态兼容回退；每条已完成的流式译文会在约 0.75 秒内合并持久化，页面转入后台或关闭前再立即刷新。刷新页面时会尝试接回仍在同一后端进程中运行的任务。后端进程重启后，未完成的模型请求不会继续，但网页可以依据源文哈希和目标语言识别 `outputs/` 中已经完成的结果。译文状态集中保存在项目内部的 `.translation-state.json`，`outputs/` 只包含实际译文；这些运行生成内容不会提交到 Git。

## 提示词优先级

程序固定使用以下优先级：

```text
硬性规则 > 用户补充要求 > 风格偏好
```

硬性规则由后端维护。“补充要求”默认留空，只用于术语指定、人名保留等额外要求。

## 安全说明

- 不要把真实 API 密钥写入源码、README 或启动脚本。
- API 密钥只应在本地界面中填写；未配置密钥时，后端不会发送 `Authorization` 请求头。
- 终端诊断日志不会打印 Authorization/API 密钥，但会完整显示待译原文、提示词和模型回复；共享终端或录屏前请注意文档隐私。
- 不要提交原文、译文、模型文件、日志、交接文档或本机专用启动脚本。
- 服务默认只监听 `127.0.0.1`，并校验本机 Host、浏览器 Origin/Fetch Metadata 及写请求类型（普通操作为 JSON，二进制导入为 `application/octet-stream`），防止网页跨站调用和 DNS rebinding。本项目仍没有面向公网部署所需的用户认证与权限隔离，请勿直接暴露到公网。
